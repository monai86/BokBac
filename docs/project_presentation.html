2. ผลการตรวจสอบโค้ดเทียบกับข้อวิจารณ์ในแผนงาน

การวิเคราะห์และตรวจสอบซอร์สโค้ดแบบบรรทัดต่อบรรทัด (Code Audit Validation)
ประเด็นวิจารณ์จากแผนงาน (BokBac-Plan.md) สถานะการตรวจ หลักฐานเชิงโค้ดและผลกระทบ (Code Evidence & Impact)
1. Suite Source-of-Truth Divergence
สลับชุดทดสอบแล้วค่าไม่สลับตาม		 ยืนยันแล้ว TestSelector.tsx อ่านจาก ALL_SUITES (legacy) แต่ตัวคำนวณใน identifyStore.recompute() สร้างขึ้นเองจาก DEFAULT_SUITES ทำให้ custom suite ใช้งานไม่ได้จริง
2. Hard Group Pre-filtering
กรองเฉพาะกลุ่มแบบเบ็ดเสร็จ		 ยืนยันแล้ว bayesianEngine.ts บรรทัดที่ 149 กรองเชื้อด้วยคำสั่ง library.filter((b) => b.group === group) ทำให้ไม่แสดงผลลัพธ์ของเชื้อที่อาจอยู่นอกกลุ่มแม้จะมี biochemical profile ตรงกัน
3. Specimen Ignored in Gate Mode
ชนิดสิ่งส่งตรวจไม่ถูกใช้กรอง		 ยืนยันแล้ว ฟังก์ชัน checkGateMatch (L81-104) ใช้ตรวจสอบเฉพาะคุณสมบัติ gramReaction และ morphology โดยไม่มีการวิเคราะห์ specimen แม้จะมีข้อมูลให้กรอกก็ตาม
4. Multi-outcome & Susceptibility Gap
ไม่รองรับค่าผลลัพธ์หลายรูปแบบ		 ยืนยันแล้ว ฟังก์ชัน mcmLikelihood (L112-138) รองรับเฉพาะการตรวจแบบ binary (+, -, V) และการตอบสนอง S/R แต่ไม่รองรับผลลัพธ์เชิงปริมาณ (เช่น K/A H₂S, alpha-hemolysis) โดยจะจัดเป็นค่า fallback 0.5
5. Coverage Scaling Omission
การสเกลความครอบคลุมหายไป		 ยืนยันแล้ว ในขณะที่ v3 มีการนำ coverageFactor มาคูณสเกลเปอร์เซ็นต์ความน่าจะเป็น แต่ใน v2 ตัวแปรนี้ถูกเก็บและแสดงแยกเท่านั้นโดยไม่ได้นำไปคูณในสูตรคำนวณ posterior จริง

3. เจาะลึกอัลกอริทึมเอนจิ้นเบส์ (Bayesian Engine Inside)

วิเคราะห์หลักการคำนวณและข้อจำกัดเชิงสถิติทางคณิตศาสตร์
Naive Bayesian Step-by-Step
  • Smoothing (การเกลี่ยค่า): ใช้ค่าคงที่ EPS = 0.02 เพื่อป้องกันความน่าจะเป็นเป็น 0 หรือ 100% (ป้องกันข้อยกเว้นการหารด้วยศูนย์ในระบบคอมพิวเตอร์)
  • Prior Odds: คำนวณจากระดับความชุกของแบคทีเรีย (Prevalence) อ้างอิงตามระดับคะแนน 1-4 (+ ถึง ++++) แปลงเป็นค่าน้ำหนักสถิติตั้งแต่ 0.05 ถึง 1.0
  • Correlation Weights (การกำจัดผลซ้ำ): ป้องกันการบิดเบือนของคะแนนสถิติเมื่อมีการทดสอบที่มีความเกี่ยวข้องกันในเชิงสรีรวิทยา (เช่น MacConkey Lactose และ TSI Lactose) โดยปรับลดน้ำหนักลงเหลือ 0.5

จุดอ่อนทางความแม่นยำ (Correlation Correction)

ฟังก์ชันลดน้ำหนักการตรวจซ้ำซ้อนในปัจจุบันยังเป็นแบบ Hardcoded (ใช้ชื่อการทดสอบย่อย) ซึ่งไม่ครอบคลุมหากมีการปรับตั้งชื่อการทดสอบใหม่ หรือนำชุดข้อมูลอื่นมาใช้แทน

สูตรการคิดค่า Typicality Index

Typicality Index (Case-fit) จะระบุว่าเชื้อตัวอย่างที่ได้ในเคสนี้ มีความเหมือนกับสายพันธุ์มาตรฐานที่ระบุไว้ในตำราเพียงใด โดยไม่ขึ้นกับว่ามีเชื้อใกล้เคียงตัวอื่นเบียดแซงหรือไม่:

typicalityProd *= (smoothedLikelihood / smoothedMaxLikelihood)
// ค่าอัตราส่วนระหว่างผลการตรวจจริง ต่อค่าผลการตรวจสูงสุดที่เป็นไปได้ของเชื้อตัวนั้น
ปัญหาความเสี่ยงของ Gate Check
  • หากผู้ใช้ย้อมสีแกรมหรือตรวจรูปร่างแบคทีเรียตัวเริ่มต้นผิดพลาด (เช่น ย้อม Gram-positive cocci ผิดเป็น Gram-negative bacilli) อัลกอริทึมจะตัดสิทธิ์การแสดงผลลัพธ์ของแบคทีเรียที่แท้จริงออกเป็น 0% ทันทีโดยไม่มีคำแจ้งเตือนหรือให้คำแนะนำที่ยืดหยุ่น

4. การประเมินด้านการออกแบบ (UX/UI & Calibration)

การวิเคราะห์พฤติกรรมการตัดสินใจของผู้เรียนเมื่อมองสถิติ
ปัญหาความเชื่อมั่นลวงตา (The % Illusion)
  • Posterior % คือค่าสัมพันธ์: ตัวเลข % ที่แสดงบนการ์ดเชื้อคือค่าที่เกิดจากการนำผลสถิติของแคนดิเดตทุกตัวในกลุ่มมาหารเฉลี่ยรวมกัน (Softmax Normalization)
  • ความเข้าใจผิด: หากใส่ข้อมูลการตรวจเพียง 1-2 อย่าง แล้วได้ค่า 98% ผู้เรียนอาจคิดว่าตรวจเชื้อเสร็จสิ้นแล้วและมีความถูกต้องสูง ทั้งที่จริงๆ เป็นเพราะตัวเปรียบเทียบในกลุ่มนั้นมีน้อย และข้อมูลยังไม่สมบูรณ์เพียงพอ
  • ตัวชี้วัดถูกฝัง: ค่าความครอบคลุมของการตรวจ (Evidence Coverage) และความตรงตามธรรมชาติของเชื้อ (Typicality) ถูกแสดงเป็นตัวหนังสือขนาดเล็กหรือซ่อนอยู่ด้านในแผงคำอธิบายเชิงลึก ทำให้อาจถูกละเลย

5. แผนดำเนินงานและลำดับความสำคัญ (Execution Roadmap)

การวางแผนแบ่งงานปรับปรุงระบบเพื่อให้ใช้งานและขยายตัวได้ยั่งยืน
การจัดลำดับความสำคัญ (Phased Roadmap)

เฟส 1: แก้ไขฐานรากและขจัดบั๊ก P0 ( Foundation & Suite Fix )

แก้ไขให้ TestSelector ดึงชุดทดสอบจาก active suite ใน identifyStore เท่านั้น ทำการเปลี่ยน keys ของแบบทดสอบในระบบจาก label เป็น testId และตั้งค่าระบบการย้ายถ่ายข้อมูล (Migration) สำหรับ saved cases เดิม

เฟส 2: ปรับปรุงเอนจิ้นคำนวณ ( Engine & Calibration )

ดึงระบบ coverageFactor กลับมาร่วมคำนวณในสูตร เปอร์เซ็นต์จริง (Calibrated Posteriors) เพิ่มระบบค่าน้ำหนักผลลัพธ์แบบยืดหยุ่น (Soft Exclusions) และสร้างฟังก์ชันการตีความผล Susceptibility แยกตามแบคทีเรีย

เฟส 3: ปรับโครงสร้างส่วนเชื่อมต่อผู้ใช้งาน ( UX & Decoupling )

ปรับปรุงการแสดงผล SpeciesCard ให้มีแถบ Metric ครบทั้ง 3 แบบ (Posterior, Typicality, Coverage) และยกระดับคำเตือนแบบปรับพฤติกรรมเมื่อผู้ใช้เลือกกลุ่มทดสอบไม่สอดคล้องกับคุณลักษณะแบคทีเรีย

เฟส 4-5: ความย้อนหลังและขั้นตอนอัตโนมัติ ( Audit & CI )

ขยายคุณสมบัติบันทึกข้อมูล (SavedCase Schema) ให้บันทึกเวอร์ชันและสถานะคงตัวของระบบ ณ ขณะนั้น และปรับปรุงขั้นตอน GitHub Actions (CI) ให้รันการทดสอบ Typecheck / Linter ร่วมด้วย
