05 / 16
Bayesian Engine

Naive Bayes Engine — 7 ขั้นตอน

แกนหลักของ BokBac: คำนวณความน่าจะเป็นจากข้อมูล MCM

Step 1Hard Exclusion

oxidase / catalase / coagulase / hemolysis mismatch → ตัดทิ้งทันที (0%)

Step 2Log-Likelihood

คำนวณ log-likelihood จาก MCM % positivity ต่อ test ทุกตัว สะสมใน log space

Step 3Fallback

Species ไม่มี MCM data → ใช้ LIBRARY +/-/V → 90/50/10% ที่น้ำหนัก ×0.7

Step 4Prevalence Priors

++++→1.0   +++→0.40   ++→0.20   +→0.10   0→0.05

Step 5Softmax Normalization

แปลง log posteriors เป็นความน่าจะเป็นที่รวมเป็น 100% ด้วย softmax

Step 6Coverage Scaling

⚠️ Legacy ใช้จริง (×coverageFactor) แต่ v4 เก็บแยกไม่ได้คูณเข้า posterior

Step 7Confidence Label

HIGH / MEDIUM / LOW / UNCERTAIN — ดูจาก posterior %, gap, #answers, typicality

BonusNext Best Test

Shannon Entropy Information Gain — แนะนำ test ที่ลด uncertainty มากที่สุด

// TestSelector.tsx L2, L35 import { ALL_SUITES } from '@/lib/dataLoader' const suite = ALL_SUITES[group] // ← legacy! // identifyStore.ts L228-277 // recompute() uses DEFAULT_SUITES ← different!
P0 — ENGINE Group Hard Pre-filter — เชื้อจริงหายได้

Engine ใช้ library.filter(b => b.group === group) ตัดเชื้อนอก group ออกก่อนคำนวณ
→ ถ้าผู้ใช้เลือกกลุ่มผิด (เช่น GPC แทน Entero) เชื้อที่ถูกต้องจะไม่ปรากฏเลย ไม่ใช่แค่ถูกลดคะแนน

P1 — BEHAVIOR DRIFT Coverage Scaling หายระหว่าง Legacy → v4

Legacy (v3):

pct = rawPct × coverageFactor // ลดคะแนนเมื่อ test น้อย

Modern (v4):

ปัญหาเพิ่มเติม

ปัญหาเชิงสถิติและ UX ที่ยังเปิดอยู่

⚠️ Multi-Outcome ไม่ทำงานจริง

Registry ประกาศ categorical, numeric ใน schema แต่ mcmLikelihood() รองรับจริงแค่ +/-/V/S/R

ผลกระทบ: TSI (K/A, A/A), hemolysis (α/β/γ), urease rapid (++) → ถูก fallback เป็น ~0.5 ทั้งหมด

⚠️ Naive Bayes ไม่มี Correlation

Engine สะสม logLik += log(likelihood) ทีละ test โดย assume independence

ผลกระทบ: IMViC, sugar panels, growth conditions ที่ correlate กัน → double-count evidence → ทำให้ posterior สูงเกินจริง

ℹ️ ไม่มี Post-hoc Calibration

% ที่แสดงเป็น raw softmax posterior ยังไม่ผ่าน temperature scaling, isotonic regression หรือ Dirichlet calibration

ผลกระทบ: "70%" อาจไม่ได้หมายความว่ามีโอกาสถูก 70% จริง — อาจ overconfident หรือ underconfident

ℹ️ Specimen ไม่เข้า Scoring

Wizard เก็บ specimen type (blood, urine, CSF...) แต่ checkGateMatch() ใช้แค่ gram + morphology

ผลกระทบ: specimen เป็น "workflow ornament" ทั้งที่ในจุลชีววิทยาจริง specimen มีผลต่อ pretest probability

ℹ️ Saved Case ไม่มี Provenance

เก็บแค่ id, answers, topSpecies, topPct — ไม่มี engine version, suite snapshot, posterior vector

ผลกระทบ: เคสเก่า replay ได้แต่ audit ไม่ได้ — ถ้า engine เปลี่ยน ไม่มีทางรู้ว่าผลเปลี่ยน

⚠️ CI ไม่ครบ

CI มีแค่ npm run test + npm run build
❌ ไม่มี lint ❌ ไม่มี explicit typecheck ❌ ไม่มี e2e

ผลกระทบ: refactor engine แล้วอาจมี type error / lint issue ที่ CI ไม่จับ
